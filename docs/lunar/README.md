# Lunar Client Patchwork prerelease

This release provides actual importable `.patchwork.json` files for inspected Windows launchers **3.7.17-ow** and **3.7.24-ow**, multiver game commit **29a43e6**, and in-game UI bundle **b6d39b2**. Pack **0.1.5** requires **Patchwork 0.9.2** and adds optional **Remove in-game promotions**. The existing four patch definitions are identical to 0.1.4: launcher cleanup, local cosmetics with cloth cape physics, automatic-update blocking and faster bootstrap fallback. Automated UI checks passed; live testing of the new cleanup is requested from the user. Earlier 0.1.4 launches of Minecraft 1.8.9, 1.17.1 and 1.21.11 passed; they do not validate the new option.

## Recover from the 0.1.0 launch failure

The old pack pinned an earlier game build. When Lunar's manifest expected the newer build, the exact-JAR guard stopped launch with `Local cosmetics patch: game file or version changed`. The error happened before Java started in the reproduced case.

1. Close Lunar, Minecraft and other Java processes. In Patchwork, use **History & restore** to restore the old Lunar session.
2. Launch the original Lunar Client once and let it finish its game update. Close Minecraft and Lunar again.
3. Update to Patchwork 0.9.2 and import the matching current pack. Preview and apply it using the steps below.

The current pack still rejects newer or damaged game builds. Restore before Lunar updates; another game build needs another matching pack. An already-updated or otherwise changed file can prevent safe history restore; retain the history/backups and resolve the changed file rather than forcing an overwrite.

## Install and test

1. Install [Patchwork 0.9.2 prerelease](https://github.com/MrCool-888/patchwork/releases/tag/v0.9.2) using its `Patchwork-Setup.exe`. Existing library/history data is retained.
2. In **Patch sources**, use `https://github.com/MrCool-888/patchwork-patches`, enable **Include pre-release patch packs**, and choose **Check now**. For a manual import, download the matching `LunarClient-3.7.24-ow.patchwork.json` or `LunarClient-3.7.17-ow.patchwork.json` and choose **Add patch file**.
3. Select the pack matching your launcher. The standard per-user installation is detected automatically. Its target folder is **your Windows user folder**, `%USERPROFILE%`, because the launcher and game are in separate subfolders. All listed operations remain inside that folder. A custom installation needs a rebuilt matching pack.
4. Before applying local cosmetics, unequip previously saved online cosmetics through the original client. Close Lunar Client, Minecraft and other Java processes.
5. Select **Remove ads and promotions**, optionally **Local cosmetics**, **Disable automatic updates**, **Faster bootstrap download fallback** and **Remove in-game promotions**, review **Preview changes**, then **Apply patches**. Local cosmetics, automatic-update blocking and faster bootstrap fallback require the launcher patch for its archive compatibility change. In-game promotion cleanup works independently. Disable automatic updates does not require local cosmetics. The ad patch can also be used by itself.
6. Start Lunar normally. On Minecraft's main menu, click the **shirt icon in the bottom toolbar** to open **Locker**. Wait for the catalog to load, select **Local Outfit**, choose a cosmetic, then click **Equip**. Use **Unequip** to remove it. The catalog may initially show zero items while loading. Local outfits are stored in `%USERPROFILE%\.lunarclient\local-cosmetics\` in per-account protobuf files.

Use **History & restore** to restore the original launcher executable, archive, game JAR, bootstrap JAR and edited in-game UI file. Keep the Patchwork data/history folder until you restore. Backups take roughly 310–335 MiB when all five options are selected. Restore refuses to overwrite files changed by another program or update. Deselecting local cosmetics and choosing **Update patches** restores the original game JAR and removes its launch guard while retaining the selected ad cleanup.

## Remove in-game promotions and test

After installing Patchwork **0.9.2**, enable prereleases in Patch sources and choose **Check now**, or download/import the matching **0.1.5** JSON. Close Lunar/Minecraft/Java, retain your existing selections, add **Remove in-game promotions**, preview and choose **Update patches**. Existing 0.1.4 history upgrades directly. The new option also works alone on the inspected original launcher; it has no dependency on local cosmetics or launcher cleanup.

The option removes the main-menu Store and Discover buttons, news carousel, coin purchase control, Medal quest/reward banners, promotional video/Discord reward cards, countdown and Wrapped cards, and the partner radio widget. It removes Locker's Shop/Purchase Lunar+ link and the store-preview checkout/back-to-store controls. Singleplayer, Multiplayer, bottom-toolbar Locker/settings, local outfit controls, owned Lunar+ colors, theme selection, ordinary alerts and preview return/exit remain available. Hidden promo components are omitted at their callers rather than mounted invisibly.

**Please test it:** launch your usual Minecraft version, wait for the menu to finish loading, confirm Store/news/coins are gone, then open Locker and confirm the shop link is gone while Local Outfit, Equip/Unequip and Cloth Cloak still work. Close and relaunch once to confirm cleanup persists. Report your version and any remaining promotion or broken control. No computer-use game test was performed for this revision, at the user's request.

Only `.lunarclient/ui/b6d39b271abae35e95be9bdadf2270e908d59548/static/index.js` is added to the patch transaction. The UI must already be extracted, with its exact original fingerprint. If it is missing, launch the original supported client once to populate it, then close the client before applying. Deselect this option and update to restore the original UI while retaining your other choices. **Keep Patchwork 0.9.2 or newer for restoration**, since older patchers cannot read this 8.7 MB JS file. Cache deletion, missing UI files or a new upstream UI bundle can remove the cleanup; restore before updating or clearing Lunar's cache. No additional cache or game verification exception is installed. See [validation](https://github.com/MrCool-888/patchwork-patches/blob/lunar-client-0.1.5/docs/lunar/GAME-PROMOTIONS-VALIDATION.md).

## Enable cloth cape physics and update an existing patch

Import pack **0.1.5**, close Lunar/Minecraft/Java, retain your selections, preview and choose **Update patches**. Verified 0.1.4 histories upgrade directly. The layout change is included in **Remove ads and promotions**; cape physics is included in **Local cosmetics**.

In Minecraft, open **Locker** using the main-menu shirt icon, select **Local Outfit**, choose **Cloaks**, select and equip a cloak. Click the **gear button beneath its character preview**, then enable **Cloth Cloak** under Cosmetic Settings. The existing cloth simulator is used; no account subscription state changes. The checkbox remains optional and its value saves with your local outfit. The global **Render Cloth Cloaks** cosmetic setting must also be enabled. The stock tooltip mentions other players; this patch's inspected outfit mutations/outgoing push remain local, and the tooltip does not establish multiplayer privacy.

The local Cloth Cloak checkbox and persisted `clothCloak=true` protobuf value were verified with an equipped **Kanji Ocean** cloak. The character preview remained stable while rotating it. No world/server movement test was performed. The inspected renderer uses the existing cloth simulation when both settings are enabled.

## Disable automatic launcher updates

Import pack 0.1.5, select **Disable automatic updates**, preview and choose **Update patches** when an earlier pack is already applied. Verified 0.1.4 histories upgrade directly without restoring first. Deselecting this option and updating restores the original automatic updater while retaining your other selected patches.

The patch blocks automatic launcher checks at startup, on timers and after update-channel changes, including server-requested force-install checks. It also disables installation on app exit. **Manual Check for updates remains available. Restore all Lunar patches before using it to update the launcher.** This option does not freeze game/runtime downloads during Minecraft launch or Overwolf's own updater. The existing local-cosmetics game guard still rejects a new/damaged game build; matching new game builds need rebuilt packs.

Both inspected launchers passed isolated updater tests and direct upgrade/deselection/restore checks. On the user's PC, 3.7.24-ow opened normally after applying this option; its startup log confirmed `Automatic launcher updates disabled by Patchwork.` Real update installation was not attempted. See [validation details](https://github.com/MrCool-888/patchwork-patches/blob/lunar-client-0.1.3/docs/lunar/VALIDATION.md).

## Starting JVM stalls

Select **Faster bootstrap download fallback**, then preview and apply or update your selection. This option is independent of local cosmetics. It supports the exact inspected Genesis bootstrap, SHA-256 `40797ad1d1449ffff7c6e7342b79a3edc8d08517505dc2d57ce9d97e0669389c`; other bootstraps need a rebuilt pack. Deselect it and update to restore the original bootstrap and remove its launcher hash exception.

The reproduced wait occurred after Java started, while Lunar downloaded a missing Maven dependency. Fabric's repository did not connect, while Maven Central served the artifact. Lunar used a 180-second connection/request deadline and nested retries: up to 45 attempts per repository before exhaustion. The patch gives connection establishment 15 seconds and tries each existing repository once. It preserves the 180-second request deadline, repository order, existing cache checks, content acceptance and failure reporting. A valid cached archive still avoids downloading.

The targeted fallback was reproduced in a controlled connection-stall test: the original downloader still waited at 30 seconds, while the patched downloader completed through the alternate repository in about 15 seconds. Fabric recovered before the patched live launches, so those successful launches establish compatibility rather than proving the earlier network incident was repaired. The underlying route problem remains unknown. This option cannot fetch an artifact unavailable from every configured repository or resolve other kinds of startup hang, and removes repeated retries for transient repository errors. See [startup investigation and validation](https://github.com/MrCool-888/patchwork-patches/blob/lunar-client-0.1.4/docs/lunar/STARTUP-VALIDATION.md) for the launch results and limits. Temporary diagnostics and profile argument changes are removed after testing; private logs and account data are not release assets.

## Scope and limits

- The launcher patch disables the shared ad visibility/rendering paths used by launchpad, Mission Control/status, Satellite and Explore. It clears layout ads, news, featured servers, marketing links, video promotions, carousel, alerts and announcements; hides Apex Hosting, sidebar external/promotional items, radio upsells and inbox promotion rows. Clearing layout alerts also removes service announcements from that feed. Launchpad and Mission Control cleanup were observed live; full UI coverage is unverified. Minecraft promotions use the separate **Remove in-game promotions** option described above.
- The game patch uses the existing all-cosmetics rendering path and intercepts outfit CRUD, outfit selection, favorites and badge equip before their mutation RPCs reach the network channel. It suppresses the inspected outgoing player cosmetic push and makes the local cloth option editable without changing global account flags. The helper needs the account's default outfit and available catalog assets. Favorite clicks are acknowledged without persistence. Emote/spray services are outside scope.
- **Previously saved online outfits are unaffected and may remain visible to other players.** Login and asset downloads still use Lunar's servers. Incoming remote cosmetic refresh behavior is unverified. This is an experimental local handler, with no promise of complete anonymity or multiplayer acceptance.
- Modified launcher archives require disabling one executable Electron ASAR integrity fuse. This invalidates the executable's publisher signature and removes embedded ASAR validation. Other fuses are preserved. See [Electron's fuse documentation](https://www.electronjs.org/docs/latest/tutorial/fuses).
- The launcher's game check accepts only the exact patched JAR when the original expected game hash matches. Missing, changed or new game builds stop launch. **Restore before updating Lunar.** Launcher updates can overwrite this patch. New originals require rebuilt packs.

## Evidence

Patchwork 0.9.2's 49-test suite passed, including the new large-JS apply/update/rollback/restore and bounds checks. The current UI components passed isolated render/click checks. Earlier validation: the 47-test suite passed, including binary/JAR validation, deterministic output, upgrade/removal, failure rollback and exact restore. Both 0.1.4 packs passed four-file preview, apply/rollback, direct 0.1.3→0.1.4 update, startup/updater removal and reselection, cosmetic removal and exact restoration on full-sized copies. The bootstrap downloader passed JVM verification and isolated loopback tests on Java 17, 21 and 25. Its original HTTP helper made nine requests to a failing first repository before a successful alternate and 45 before exhausting one repository; the patched helper made one in both cases. Strict bootstrap verifier and updater regression tests passed for both launchers. Unaffected archive members were compared byte-for-byte, edited JavaScript passed syntax checks, JAR CRCs passed, and exactly one executable byte changed. Four original game classes changed and two independently written helper classes were added. The new cloak menu change replaces two three-byte permission checks with the same-length stack-equivalent instructions, preserving class layout, branches, exceptions and stack frames. Its regression probe checks the actual six-byte delta and rejects duplicate application. The actual modified Java service stubs passed local CRUD/persistence/unlock tests with JVM verification; only login reached the fake network channel. Both launcher ad hooks, exact patched-JAR guards and updater behavior passed isolated JavaScript tests.

On 2026-10-10, the old launch failure was reproduced and then resolved by restoring, updating the original game and applying 0.1.1. The patched game reached the main menu. Locker loaded **5,665 cosmetics**; **2021 City Bandanna** rendered, equipped and unequipped in Local Outfit. Its local protobuf file changed for both actions. The test selection was removed afterward. No multiplayer server or world was joined, and no packet capture was performed. Launcher 3.7.17 was tested on copies only.

Source and reproducible pack instructions are in `source/lunar` in the tagged patch repository and source release asset. No Lunar executables, original game classes, archives, models or textures are distributed.
