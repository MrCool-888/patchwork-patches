# Proton VPN 5.1.10 / pack 1.7.1 validation

Verified November 26, 2026, against the Windows x64 **5.1.10.0** installation and with **Patchwork 1.1.1**.

## Build and scope

- The x64 installer matched the official release asset SHA-256 `67ee2e03322abc313430c0aeb2702db5ab09b070cd7e97c4636b44523589cf56`. Windows verified its Proton AG signature. The extracted client executable and ten relevant DLLs matched the installed files byte for byte. [Proton VPN 5.1.10 release](https://github.com/ProtonVPN/win-app/releases/tag/v5.1.10)
- Pack 1.7.1 has **15 selections and 62 operations** across ten DLLs. It retains the existing catalog ID and color options. It includes the guest sign-in selection, with the embedded helper rebuilt against 5.1.10.
- All 52 distinct patch-target methods appear in the signed 5.1.10 files. The 5.1.9-to-5.1.10 comparison matched **169 of 171** methods; the two differences are compiler-generated `UserAuthenticator` state machines rebuilt by the upstream .NET 10 compiler. The four guest hook targets (`SignInPageView..ctor`, `GetUserAsync`, `AutoLoginUserAsync`, `LogRefreshToken`) match exactly.
- The service, networking and DNS binaries and the client resource indexes retain their official 5.1.10 bytes in the patched runtime fixture. This covers the components relevant to Proton's LAN reconnect and default-connection display changes.
- Repeated generation produced SHA-256 `ee7d226dd1c771255d0b81014f1b987625585d907cbb77bbc6fc7b062fdb4810` for the JSON pack. The updated generator still reproduces the 5.1.9 pack byte for byte.

## Patchwork checks

- Patchwork previewed all 15 selections together against the installed folder while Proton VPN was running. The installed file hashes were unchanged after testing.
- On a disposable target, each selection previewed without writes. Two combined previews produced identical hashes. Apply matched the preview, custom colors persisted through update and reselection, and restoration returned all ten changed DLLs to their original bytes.
- The engine rejected a 5.1.9 executable and a tampered 5.1.10 DLL before writes. The applied authentication DLL contains the embedded guest hooks, and the original token-prefix logging method is cleared.
- A normal window close request left the Proton process active. The test harness used a fixture-specific process name for apply and restore. The distributable pack uses Patchwork's standard process check.

## Runtime checks

The copied client fixture contained the same ten patched DLLs as the final Patchwork apply.

| Probe | Passed |
| --- | ---: |
| Server and account eligibility selection, announcements | 55 checks |
| Settings, navigation, Accelerator service request | 13 checks |
| Telemetry, local cooldown, saved settings | 19 checks |
| Embedded guest hooks in the actual authentication DLL | 3 checks |
| Guest lifecycle, cleanup, deadlines, cancellation, retry | 52 checks |
| Native WinUI guest navigation and cancellation | 21 checks |
| WinUI color and brush resources | 54 resources across Light and Dark |

The native WinUI fixture also verified the accent and switch colors in both themes, shared promotional controls, restricted and available rows, four explicit Upgrade buttons, and the guest button's insertion, busy state, page-transition cancellation and retry. The app contains .NET 10.0.14. The console behavior probes ran on .NET 10, and the WinUI probes used the packaged .NET and Windows App Runtime.

Live sign-in, guest session tunnel, tunnel connectivity, reconnect behavior, DNS filtering and routing remain untested with the pack applied.
