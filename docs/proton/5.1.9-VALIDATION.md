# Proton VPN 5.1.9 / pack 1.6.0 validation

Validated November 5, 2026, using extracted official Windows x64 **5.1.9.0** files and the production **Patchwork 1.1.1** engine. Tests used isolated files and history.

## Target and changes

- Official release: [v5.1.9](https://github.com/ProtonVPN/win-app/releases/tag/v5.1.9), source commit `bd8380fe92c2b07f07ee6e48858307f12780fcb9`.
- Installer SHA-256: `8454eba06a37c0a636ec8dcfe6a7a823a68a78ee8fe2eeda2d651cd5cd6c3d70`, matching GitHub's release digest; Authenticode verified **Proton AG**.
- The installer was extracted without running it.
- The new pack retains all **15 selections / 62 operations**, IDs, descriptions, versions, and color defaults. Changes are the target version and original-file fingerprints, pack version **1.6.0**, source provenance, and guest helper rebuilt against 5.1.9.
- The historical catalog ID `proton-vpn-win-5-1-8-r1` is intentionally retained for catalog replacement. The pack's `appVersion` and fingerprints select 5.1.9.
- The updated generator reproduces the existing 5.1.8 JSON byte for byte when given its original helper and original app files: SHA-256 `8c4d7ace14103abf3011725db409478003309bf2545b8dfa1369dbcc644036a9`.

## Static checks

Compared 171 original methods covering patch targets, authentication, and the sign-in view model. **162** have identical resolved CIL, locals, and exception regions. Eight differ only in upstream build-directory strings used in logging. The remaining difference is the compiler-generated name of the countries getter lambda; its referenced body is identical. After those explicit normalizations, all **171** match. This comparison does not assert whole-application equivalence.

The upstream source diff was also inspected: 5.1.9's server-cache changes and new `auth/v4/refresh` endpoint are retained. The pack edits the countries projection and token logging method rather than replacing the cache update or token-refresh implementation.

REA confirmed the server assembly's 5.1.9.0 identity, x64 IL-only .NET 8 classification, target getter bodies, and settings field. Artifact evidence `ev_134c2eecab6f6fc2bfddafb34ee857c5607d0c012cd06542e303c91b347f65c6`; member evidence `ev_eae944293356824d1bf3a3dee5a43132085b05fefe076045e1e8d26398f4e820`. REA's member signature coverage is partial because its parser does not decode these generic signatures; Mono.Cecil and the runtime probes provide the complementary typed checks.

## Production engine and restore

`source/proton/ValidatePack.cs` uses fresh disposable targets and separate history. Passed:

- All **15 individual previews**, with no target writes.
- Repeated combined previews with identical output hashes.
- Combined apply matching the preview and expected bundle/version/selection history.
- Nondefault colors stored in history, color-patch deselection, and reselection.
- Restoration of every tracked file to its original SHA-256.
- Rejection of a 5.1.8 executable and a tampered original before writes.
- A final default-color apply for the runtime fixtures.

The candidate-integrity probe also verified both embedded helper hashes, removal of token-prefix logging, preservation of the original theme selector, two generated theme dictionaries, byte-exact restoration of all ten changed assemblies, and deterministic preview after restoration.

## Copied-client runtime checks

All tests use in-memory fixture dependencies; they create no real sessions or VPN connections.

| Probe | Passed checks |
| --- | ---: |
| Selector, exact-server intent, account restrictions, announcements | 55 |
| Settings, navigation, effective Accelerator request | 13 |
| Telemetry, cooldown, restrictions, saved settings | 19 |
| Embedded hooks executed in the actual authentication DLL | 3 |
| Guest lifecycle, cleanup, deadlines, cancellation, retry | 52 |
| Native WinUI guest navigation and cancellation | 21 |

The native theme/promotion probe loaded **54** generated color/brush resources, resolved accent and switch colors in Light and Dark, and checked shared banners, restricted-row behavior, and four explicit Upgrade buttons. The packaged 5.1.9 native apphost and Windows App Runtime were used for these UI probes. Initial attempts using the generic installed dotnet host failed to start the WinUI fixture; the apphost-based run passed.

Compiler compatibility warnings for the supplied WinUI/WinRT/Windows SDK projection versions were observed; the copied-DLL and native UI runs passed with the supplied runtime assemblies.

## Limits

No real 5.1.9 VPN tunnel, network routing, DNS behavior, LAN reachability, NetShield filtering, throughput, installed-client restart/reconnect, or live guest API lifecycle was exercised in this update. Existing server-side eligibility remains authoritative. These checks establish isolated patch compatibility and fixture behavior; they do not establish live VPN behavior.
