# Lunar pack source

The JSON assets contain declarative text and byte-range edits plus our own Java helper. No original Lunar binaries/assets/classes are included. `patch_lunar.py` supplies the inspected class parser/stub code generator and the original 3.7.17 launcher transformations; `build-pack.py` adds the 3.7.24 rules and converts these transformations to Patchwork operations. The standalone Python installer's main function is not used by Patchwork.

Run `python source/lunar/build-pack.py --version 3.7.24-ow --original-dir C:\path\to\original-copies --output-dir build` from the repository. The original directory must contain `app.asar`, `Lunar Client.exe`, and `lunar.jar`; all hashes are checked against the inspected originals. Use `--version 3.7.17-ow` for that inspected version. Python 3 and its standard library are sufficient. The bundled helper classes are independently written code compiled for Java 17.

The fixed patched-JAR SHA-1 corresponds to the included helper bytes and the released Patchwork 0.9.0 .NET Framework transformer. It was produced twice identically and checked through complete pack preview/apply/restore. To change the helper, compile `LocalCosmetics.java` with a Java 17-capable compiler against the local original `lunar.jar`, writing to `helper`. Regenerate a provisional pack; run its JAR operations through the real Patchwork transformer; calculate the resulting JAR's SHA-1; regenerate with `--game-sha1 HASH`; then bump the pack version and run all validation before publishing. Changing class/compiler bytes can change that digest.

`LocalCosmeticsTest.java` exercises the actual modified service stubs with a fake RpcChannel. Compile it against the generated patched JAR, then run `java -ea -Xverify:all -cp test-classes;patched-lunar.jar LocalCosmeticsTest C:\path\to\fresh-test-outfit-folder`. The test uses a separate explicit local outfit directory. It must report that only login reached the fake channel; it does not establish real network privacy or Minecraft rendering behavior.

For launcher tests, extract only changed entries into a scratch folder and run `node --check --input-type=module` on their bytes. Check the shared ad hook, game guard, all unaffected archive/JAR members, JAR CRCs, the single fuse byte, full transaction failure rollback, selection removal and exact restore. Review `docs/lunar/README.md` before applying to an installation.

Compile `ValidatePack.cs` with the Windows Framework compiler, referencing the released `Patchwork.exe` and `System.Web.Extensions.dll`. Place the probe beside the referenced Patchwork executable, then run `ValidatePack PACK_JSON ORIGINALS_DIR NEW_SCRATCH_DIR`. It performs full-sized preview, deterministic JAR, partial-write rollback, apply, selection removal and exact restore tests only on fresh scratch copies. Its staged files are copyrighted local targets for private testing; do not upload them.
