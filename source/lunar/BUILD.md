# Lunar pack source

The JSON assets contain declarative text and byte-range edits plus our own Java helper. No original Lunar binaries/assets/classes are included. `patch_lunar.py` supplies the inspected class parser/stub code generator and the original 3.7.17 launcher transformations; `build-pack.py` adds the 3.7.24 rules and converts these transformations to Patchwork operations. The standalone Python installer's main function is not used by Patchwork.

Run `python source/lunar/build-pack.py --version 3.7.24-ow --original-dir C:\path\to\original-copies --output-dir build` from the repository. The original directory must contain `app.asar`, `Lunar Client.exe`, `lunar.jar` and `genesis-0.1.0-SNAPSHOT-all.jar`; all hashes are checked against the inspected originals. Use `--version 3.7.17-ow` for that inspected version. Python 3 and its standard library are sufficient. The bundled helper classes are independently written code compiled for Java 17.

Pack 0.1.6 requires multiver commit `29a43e6149a6bcbeb472b83c0290fa807e351a17`, original JAR SHA-256 `f4a6a62df2d548906f272d2d0dc906b6caae6f3592f9e2dae918783324bf3cca` and SHA-1 `3a30454c0e076f6feee2246c5969d006414f4307`. The patched-JAR SHA-1 is `83127fc392298424f53eef71f6bdb8bb61a7a2b6` for the included helper bytes, cloth-menu splices and Patchwork 0.9.1 .NET Framework transformer. Earlier packs 0.1.1/0.1.2 produced `bd3d081b9c8556a1b0c98c156bc0c1b783ec5bad`. The result was produced identically and checked through complete pack preview/apply/restore. The manager class, outgoing-push method and cloak settings class are pinned to this build; inspect those again for every new game build. To change the helper, compile `LocalCosmetics.java` with a Java 17-capable compiler against the local original `lunar.jar`, writing to `helper`. Regenerate a provisional pack; run its JAR operations through the real Patchwork transformer; calculate the resulting JAR's SHA-1; regenerate with `--game-sha1 HASH`; then bump the pack version and run all validation before publishing. Changing class/compiler bytes can change that digest.

`LocalCosmeticsTest.java` exercises the actual modified service stubs with a fake RpcChannel. Compile it against the generated patched JAR, then run `java -ea -Xverify:all -cp test-classes;patched-lunar.jar LocalCosmeticsTest C:\path\to\fresh-test-outfit-folder`. The test uses a separate explicit local outfit directory. It must report that only login reached the fake channel; it does not establish real network privacy or Minecraft rendering behavior.

For launcher tests, extract only changed entries into a scratch folder and run `node --check --input-type=module` on their bytes. Check the shared ad hook, game guard, all unaffected archive/JAR members, JAR CRCs, the single fuse byte, full transaction failure rollback, selection removal and exact restore. Review `docs/lunar/README.md` before applying to an installation.

Compile `ValidatePack.cs` with the Windows Framework compiler, referencing the released `Patchwork.exe` and `System.Web.Extensions.dll`. Place the probe beside the referenced Patchwork executable, then run `ValidatePack PACK_JSON ORIGINALS_DIR NEW_SCRATCH_DIR [PREVIOUS_PACK_JSON]`. It performs full-sized preview, deterministic JAR, partial-write rollback, apply, updater deselection/reselection, cosmetic removal and exact restore tests only on fresh scratch copies. Supplying the previous 0.1.5 pack also verifies direct upgrade; removing the updater must recover the current clean/cosmetics selection built from originals. Its staged files are copyrighted local targets for private testing; do not upload them.

Run `python source/lunar/test-cloth.py ORIGINAL_JAR PATCHED_JAR` to check the two cloak-only, stack-equivalent, same-length edits. The probe compares the actual modified class to the generator result, checks that exactly six bytes change and rejects duplicate patching. The physics implementation remains the existing renderer/simulator; only the two local settings checks change. Home layout edits are scoped text replacements in `build-pack.py` and must match once in each inspected original.

For pack 0.1.2's automatic-update option, extract `dist-electron/electron/main.js` from both the original and staged patched ASAR into private scratch files. Run `node source/lunar/test-updates.cjs 3.7.24-ow ORIGINAL_MAIN_JS PATCHED_MAIN_JS` (or 3.7.17-ow). The probe executes the actual updater class and server-push handler in a VM with an isolated native updater. It checks startup/timer/channel/server blocking, pending automatic installs, install-on-exit settings, manual checks/install and preservation of an in-flight manual request. It performs no network calls or real installations.

Pack 0.1.4 originally added `patch_startup.py`. Its exact class and initializer checks split the original shared duration into a 15-second connection duration and the unchanged 180-second request duration. Two same-length loop-bound edits make each existing repository attempt once. In that release, only the HTTP helper class changed in Genesis; other members and cache acceptance logic remained byte-identical. The 0.1.4/0.1.5 JSON embedded ten short splices totaling 24 inserted/replacement bytes, plus a separate non-overlapping launcher verification edit. No runtime agent is part of this option.

The original Genesis SHA-256 is `40797ad1d1449ffff7c6e7342b79a3edc8d08517505dc2d57ce9d97e0669389c`, SHA-1 `ea2f19ae5fcb3941df77637b184a1ff02157d6b1`. The 0.1.4/0.1.5 Patchwork Framework transformer result was SHA-1 `106f52481af4a63ba559bb817e9ccea087f387f7`; the current 0.1.6 result with Patchwork 0.9.2 is `12ec07a090a9d071363d1884a958682cd00c7d91`; pass another independently verified transformer result with `--bootstrap-sha1` if needed. The launcher exception requires both this result and the original upstream expected hash. Regenerate and validate rather than allowing arbitrary modified hashes.

`DownloaderTest.java` reflects the actual original/modified downloader. Compile with Java 17 or later against the JDK HTTP server module; run `java --add-modules java.net.http,jdk.httpserver -Xverify:all -cp TEST_CLASSES DownloaderTest original ORIGINAL_GENESIS_JAR` and then `... DownloaderTest candidate PATCHED_GENESIS_JAR`. Set `-Dlunar.testRoot=PRIVATE_SCRATCH` for the cache fixture root and cap each child process at 20 seconds. The fixture tests 503 fallback, 404 skipping, predicate rejection, exhaustion and a valid Maven cache hit; it performs only loopback requests. Run on Java 17, 21 and 25. This test measures attempt counts; the bounded `test-stalled-fallback.py` A/B regression separately establishes quicker fallback under a simulated connection stall. The latter requires a three-second TEST-NET timeout before running and uses a loopback fallback, with no live installation or network-settings changes. Its result does not establish a live network incident's underlying cause.

Extract the original/staged launcher main JS and run `node source/lunar/test-startup.cjs 3.7.24-ow ORIGINAL_MAIN PATCHED_MAIN` (also 3.7.17-ow). It verifies exact bootstrap acceptance, changed/upstream hash rejection, compatibility with the cosmetics exception, and ordinary/missing file handling. Retain updater tests and full-sized five-file upgrade, deselection, rollback and exact restoration tests. See `docs/lunar/STARTUP-VALIDATION.md` for the live matrix; never upload the private originals, instrumented launch arguments, profile database backup or raw logs.


Pack 0.1.6 additionally appends a constant-pool reference to `local/lunar/BootstrapDownloads.send` and redirects only the multi-repository method's single `HttpClient.send` instruction to that static helper. The replacement has the same length and stack effect. Original constant-pool entries, branch offsets, exception tables and stack frames stay intact. The direct single-URL method is byte-identical to 0.1.5. Two independently written helper classes are added; all other original Genesis members remain unchanged.

`BootstrapDownloads.java` stores connection-timeout origins only in the current JVM. It catches only `HttpConnectTimeoutException`; HTTP status failures, request timeouts, generic I/O errors and interruptions are not memoized. Origins normalize scheme, host and default port. A new process starts with an empty set. No launch arguments, credentials, properties or URLs are logged. Compile for Java 17 into `helper` and include **both** `local/lunar/BootstrapDownloads.class` and `local/lunar/BootstrapDownloads$Origin.class`. For example, `javac --release 17 -d source/lunar/helper source/lunar/BootstrapDownloads.java`. The shipped bytes were built with ECJ's Java 17 target; another compiler may produce a different result hash, which must be regenerated and verified through the actual Patchwork transformer and strict launcher guard.

Compile `BootstrapDownloads.java` and `BootstrapDownloadsTest.java` into a separate unit-test directory, then run `java -Xverify:all -cp UNIT_CLASSES local.lunar.BootstrapDownloadsTest`. The fake-client fixture checks origin normalization/independence and that non-connection failures and response bodies are preserved. Run on Java 17, 21 and 25.

Compile `BatchFallbackTest.java` separately with the JDK HTTP server module. Run `java --add-modules java.net.http,jdk.httpserver -Xverify:all -cp TEST_CLASSES BatchFallbackTest previous PREVIOUS_GENESIS_JAR FRESH_CACHE`, then repeat with `candidate PATCHED_GENESIS_JAR ANOTHER_FRESH_CACHE`. Cap each child process at 60 seconds. The previous JAR must be the 0.1.4/0.1.5 patched bootstrap. Keep the new helper out of TEST_CLASSES so each JAR loads its own implementation. The fixture requires a three-second silent TEST-NET connection timeout, alters only its isolated JVM's repository instances, then downloads three distinct coordinates through a loopback alternate and validates their archives. It changes no OS network settings or live cache. Both tests use fresh directories. See `docs/lunar/STARTUP-BATCH-VALIDATION.md` for the observed 45.2-second versus 15.2-second result and live compatibility checks.

The other four patch definitions are unchanged from 0.1.5. The full transaction probe also checks startup and promotion removal/reselection, promotion-only one-file restoration and 0.1.5 upgrade. In-game UI requirements and tests remain documented in `GAME-PROMOTIONS-VALIDATION.md`; no new patcher release is needed beyond 0.9.2.
